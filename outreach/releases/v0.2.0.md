# CAPYN v0.2.0 — Portable Authority

CAPYN v0.2 turns the public alpha into an end-to-end authority rehearsal: draft
one bounded mandate, carry it as a locally verifiable Authority Passport, run a
real policy decision, and inspect the evidence without mistaking any of those
artifacts for activated production authority.

## What is new

- **Mandate Studio** turns one consequential action into an explicit,
  browser-local authority draft and typed integration code.
- **Authority Passports** travel in URL fragments, validate locally, and cover
  their canonical payload with a recomputed SHA-256 digest.
- **Decision proofs** preserve the synthetic authorization and ordered evidence
  sequence in a client-side verifier.
- **Boundary File 001** shows the full procurement-agent journey from request to
  mock execution.
- **Private boundary briefs** give prospective design partners a no-account,
  no-upload way to make the first conversation specific before choosing a
  transfer channel.
- **Public package archives** for `@capyn/types`, `@capyn/policy-engine`, and
  `@capyn/sdk` are documented, allowlisted, and clean-room install verified.

## Security and release quality

- Patched the transitive `deepmerge-ts` graph vulnerability by moving to 8.0.0.
- Added a production dependency audit to CI and weekly Dependabot coverage for
  pnpm and GitHub Actions.
- Passed the complete repository gate, 100 automated tests, both deployment
  smoke suites, 29 public routes, nine protected dashboard routes, and an
  isolated install/import test of all three package tarballs.

## Explicit boundary

The hosted alpha is synthetic and memory-backed. It uses mock execution, can
reset during deployment, contains no customer data, and does not move real
money. Passport and proof digests demonstrate payload integrity—not identity,
signature, activation, approval, or execution. The npm package manifests are
release-ready, but registry publication remains pending an owner-controlled
`@capyn` scope and authenticated npm account.
